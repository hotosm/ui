# Loading Strategies

How to avoid flash of undefined custom elements (FOUCE) when using HOT UI.

## The Strategy

Register every custom element **before anything renders**, then keep a
pure-CSS backstop for anything that slips through. Cherry-picking
components per page saves some bytes but reintroduces FOUCE whenever the
import list drifts - we trade a one-off, well-cached download for zero
maintenance.

## Single-Page Apps (Vite, Webpack, etc.)

Import everything in your entry file, before the app mounts:

```js
import "@hotosm/ui/dist/style.css";
import "@hotosm/ui/dist/webawesome-all.js"; // registers every wa-* element
import "@hotosm/ui/dist/components/header/header.js"; // hot-* components you use
```

Because these are static imports in the entry chunk, all elements are
defined before the first render. No cloaking, no pop-in, no layout shift.

Keep WebAwesome in its own chunk so app deploys don't invalidate the
browser-cached copy (see README for the `manualChunks` snippet).

## Multi-Page Apps (HTMX, plain HTML, CDN)

Every navigation is a full page load, so the browser repeats the startup
work each time. Three pieces:

1. **Load modules via jsDelivr `/+esm`** (rewrites bare-module specifiers,
   so no import map is needed):

   ```html
   <script
     type="module"
     src="https://cdn.jsdelivr.net/npm/@hotosm/ui@1.0.0/dist/webawesome-all.js/+esm"
   ></script>
   <script
     type="module"
     src="https://cdn.jsdelivr.net/npm/@hotosm/ui@1.0.0/dist/hotosm-ui.js/+esm"
   ></script>
   ```

2. **Inline a few critical theme tokens** in `<head>` so first paint looks
   right before the CDN CSS arrives. Keep it small - stabilise first
   paint, don't duplicate the token system:

   ```html
   <style>
     :root {
       --wa-color-brand-fill-loud: #d43f3f;
       --wa-color-brand-border-loud: #ed5c5e;
       --wa-color-brand-on-loud: #ffffff;
       --hot-color-neutral-900: #404248;
       --hot-color-neutral-50: #f3f3f3;
     }
   </style>
   ```

3. **Load fonts with a `<link>`, never a CSS `@import`** (an `@import`
   serialises the font download behind the stylesheet - see
   [#178](https://github.com/hotosm/ui/issues/178)). The exact tags are in
   the README under "Fonts".

## The Backstop: `wa-cloak`

Add the `wa-cloak` class to `<html>` (or any wrapper). It's pure CSS,
shipped in WebAwesome's `utilities.css` (included in `style.css`): the
element stays hidden while it contains any undefined custom element, and
reveals itself the moment everything registers - or after 2 seconds, so a
broken load can never blank the page forever.

```html
<html class="wa-theme-default wa-palette-hotosm wa-cloak"></html>
```

With everything registered up front the cloak never actually engages - it
only exists to catch regressions. MPAs that prefer per-element pop-in over
whole-page hiding can use `:not(:defined) { visibility: hidden }` on
specific elements instead.
